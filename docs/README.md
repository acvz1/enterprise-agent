# 项目学习文档

这些文档现在按“后端项目经验接近 0”的起点编写。不要一次全部读完。

## 现在先完成“读懂原项目”（预计 3 个专注学习日）

这里的 3 天不是按日历强制排课，而是按每天投入 4～6 小时估算。完成标准不是“文件都翻过一遍”，而是能自己画出登录、上传、问答三条调用链。

1. [00-先从这里开始](00-start-here.md)：先知道项目解决什么问题，以及最常见的后端词是什么意思。
2. [02-项目结构与三条调用链](02-architecture-and-call-chain.md)：知道一次请求经过哪些文件。

能说清主要模块的输入、输出和下一步调用谁以后，再进入 [06-第一部分：修好文档上传](06-stage-1-reliable-ingestion.md)。

## 之后按需阅读

- [01-原项目检查结果](01-upstream-audit.md)：哪些代码保留、删除或准备修改。
- [03-功能模块与工作量预估](03-secondary-development-roadmap.md)：按每部分功能分别估算学习和完成所需时间。
- [04-面试时怎么说](04-interview-ownership.md)：区分上游代码和你的个人工作。
- [05-运行验证记录](05-baseline-verification.md)：保存测试命令和结果，暂时不用细读。
- [为什么后端选择 Java](adr/0001-use-java-for-ai-backend.md)：面试被问到技术选型时再看。

## 阅读规则

- 技术词第一次出现时，先看括号里的白话解释。
- 先理解“输入是什么、输出是什么、下一步交给谁”，再看类名和框架注解。
- 不要求背文件名。能沿着一次请求找到下一个模块就够了。
