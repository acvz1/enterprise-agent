# 原项目检查结果

## 1. 为什么要先检查，而不是直接加功能

这个项目来自 GitHub。接手别人的代码时，第一步不是马上新增 Agent，而是先回答：

- 原来的项目能不能运行？
- 哪些功能真的写了，哪些只是 README 里提到了？
- 哪些代码可以复用？
- 哪些错误会影响后续开发？

这种接手检查也叫“项目审计”。它不是安全黑客审计，只是系统地摸清代码现状。

## 2. 我们保留了什么

| 保留内容 | 它做什么 | 为什么保留 |
|---|---|---|
| 登录和接口权限 | 判断用户是谁、能访问什么接口 | 企业后端的必要基础，不需要重新造一套 |
| 文档增删改查 | 保存、修改、分类和删除文档 | 给知识库提供真实业务数据 |
| 文件解析 | 从 PDF、Word 等文件提取文字 | 属于通用能力，直接复用更合理 |
| 基础知识检索 | 根据问题查找相关文档 | 后面可以在它上面增加来源、权限和更好的排序 |
| 对话记录 | 保存最近几轮聊天 | 后面会成为大模型上下文的一部分 |
| 大模型连接 | 根据配置调用不同模型 | 我们把精力放在 Agent 流程，而不是重写 HTTP 调用 |
| 流式回答 | 回答生成一点，前端显示一点 | 后面可以展示 Agent 调工具的过程 |
| Vue 前端 | 登录、文档和聊天页面 | 用来演示后端能力即可 |

## 3. 我们删除了什么

### 根目录的 `node_modules`

这是开发者本机安装出来的依赖，不应该提交到 Git。项目里误提交了 374 个相关文件，已经删除。

### Elasticsearch 占位配置

配置文件和 Docker 里写了 Elasticsearch，但 Java 代码并没有创建客户端、建立索引或执行查询。保留会让人误以为项目已经实现 Elasticsearch 检索，所以先删除。

删除的是“只有名字、没有调用链”的假接入，不是放弃 Elasticsearch。后续会把它作为正式功能重新加入：MySQL 保存业务数据，Redis 负责语义相似搜索，Elasticsearch 负责关键词搜索和条件过滤，并为同步、重建索引、删除文档和查询失败补测试。

### GraalVM 和三套压测工具

它们不是当前主线，而且部分配置绑定了原作者的电脑。同时保留多套没有真实数据支撑的工具，只会增加运行难度。

### 原来的大批教程和面试稿

这些内容不是你的项目贡献，也不帮助理解当前调用链。我们只保留针对这个二开项目重新写的学习文档。

## 4. 已经做的小修改

### 补全二次开发仓库的源码

你的 `origin` 继续指向个人仓库，用于提交二次开发代码；另外增加 `upstream` 指向原项目，只用于获取原始版本。已经从固定提交 `82fa410` 补回缺失的 72 个主 Java 源文件、数据库初始化文件、Maven Wrapper 和 29 个前端源码文件。

恢复时没有整体合并上游仓库：根目录 `node_modules`、GraalVM 配置、性能测试和大批教程仍然排除，现有学习文档和已经修改的三个 Java 文件也没有被覆盖。

### 修复 Maven 无法启动

原项目写死了原作者电脑上的 JDK 路径。换一台电脑就会失败，现在已经删除这个限制。

### 不再随便补文档

原逻辑在没有找到足够相关文档时，会把知识库里的其他文档随便塞给大模型。这会让回答混入无关内容，现在已经删除。

### 限制大模型自由发挥

现在提示词要求：知识库证据不够时直接说“不足以回答”，不能偷偷使用模型自己记住的事实补答案。

### 修复混合搜索的权重失效

原接口虽然接收“语义搜索占 60%、关键词搜索占 40%”，代码却没有使用这两个数字，只是把两个列表拼起来。

现在使用 RRF（把两份排名按名次和权重合并的方法）重新排序，并补了测试。

## 5. 还没有修的四个核心问题

### 文档后台处理不可靠

`@Async` 标记的方法在同一个对象内部直接调用，没有经过 Spring 包装层，因此很可能并没有真正进入后台线程。这是第一阶段要亲手修的内容。

### 搜索结果不能稳定追到原文

向量搜索找到一段文字后，当前代码又拿整段文字去 MySQL 反查。相同文字可能出现多次，而且会增加数据库查询次数。后面要让每个向量直接保存文档 ID 和段落 ID。

### 文档权限没有进入搜索过程

系统目前主要限制“能不能调用接口”，还没有完整限制“这个用户能不能搜到这篇文档”。企业知识库必须在搜索阶段就排除无权查看的内容。

### Elasticsearch 还没有真正接入

当前关键词搜索仍由 MySQL 完成。后续会让 Elasticsearch 真正进入“文档入库”和“用户搜索”两条调用链，用它做 BM25 关键词排序、字段过滤和结果高亮，再与 Redis 的向量搜索结果合并。只有代码、数据同步和测试都完成后，简历才会写“接入 Elasticsearch”。

## 6. 当前可以怎样描述项目

可以说：这是一个已经能运行的 Java 知识库问答底座，具备登录、文档管理、基础检索、大模型问答和流式输出。

不能说：它已经是生产级 Agent，也不能说已经完成可靠后台任务、文档级权限、可信评测、MCP 或多 Agent。

另外，上游没有明确许可证。在得到授权前只用于本地学习，不公开分发代码。
